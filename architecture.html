2. Pipeline d'indexation (automatique, toutes les 5 min)

Chaque fichier des partages est découpé en chunks, tagué avec le GUID du groupe Entra autorisé, vectorisé, puis indexé.

flowchart LR
  F[("Fichier dans
admin-share / alluser-share")] --> DS["Data source
af-ds-admin / af-ds-alluser
(type azurefile)"]
  DS --> IX["Indexer af-indexer-all-*
schedule PT5M · incrémental
contentAndMetadata"]
  IX --> CR["Document cracking
extraction texte + métadonnées"]
  CR --> SP["SplitSkill
pages 2000 car. · overlap 400"]
  CR --> CO["ConditionalSkill
injecte le GUID du groupe du share"]
  CO --> SP2["SplitSkill
GUID → tableau group_ids"]
  SP --> EM["AzureOpenAIEmbeddingSkill
text-embedding-3-small"]:::ai
  EM --> PJ["Index projections
1 doc d'index par chunk"]
  SP2 --> PJ
  PJ --> IDX[("af-index-all
chunk · vecteur 1536 · title=URL source
group_ids (permissionFilter)")]:::sec

  classDef ai fill:AI_FILL,stroke:AI_FILL,color:AI_FG
  classDef sec fill:SURF,stroke:WARN,stroke-width:2px,color:TXT

Limites : suppression de fichiers non détectée ; filtrage par groupe du share (pas les ACL NTFS) ; nouveau fichier visible après le prochain run + traitement.

3. Parcours d'une question (RAG agentique)

Les étapes en rose sont faites par un modèle IA.

sequenceDiagram
  autonumber
  actor U as Utilisateur (Teams / Copilot)
  participant A as Agent Foundry
agent-shareiarag
  participant L as gpt-5-mini
  participant K as Knowledge base
af-kb-all
  participant I as Index af-index-all
  participant E as text-embedding-3-small

  U->>A: Question (FR ou EN) + jeton utilisateur (OBO)
  rect AI_SOFT
    A->>L: 🧠 IA : décide d'appeler knowledge_base_retrieve
  end
  A->>K: retrieve (via MCP af-kb-all-mcp) + identité utilisateur
  rect AI_SOFT
    K->>L: 🧠 IA : planification (effort low)
reformule / découpe en sous-requêtes, cross-langue
  end
  rect AI_SOFT
    K->>E: 🧠 IA : vectorise les sous-requêtes
  end
  K->>I: Recherche hybride (vecteur HNSW + mots-clés fr.microsoft)
+ filtre group_ids ∈ groupes de l'utilisateur
  rect AI_SOFT
    I->>I: 🧠 IA : semantic ranker (config « sem ») re-classe les chunks
  end
  I-->>K: Chunks autorisés uniquement
  K-->>A: extractiveData (passages + références)
  rect AI_SOFT
    A->>L: 🧠 IA : rédige la réponse en anglais,
citations 【…】, règle « no-answer »
  end
  A->>A: Construit « 📂 Open files » : URL source → func-shareiarag-dl/api/f/…
  A-->>U: Réponse + citations + liens fichiers

Sans jeton utilisateur (clé admin seule) → 0 résultat. Un membre d'un seul groupe ne voit que son share.

4. Ouverture d'un fichier depuis un lien

Aucune IA ici : contrôle d'accès puis redirection vers une URL temporaire.

sequenceDiagram
  autonumber
  actor U as Utilisateur
  participant F as Function func-shareiarag-dl
  participant EA as App Service Auth (Entra)
  participant S as Azure Files
  participant O as Office Online

  U->>F: GET /api/f/admin-share/dossier/facture.pdf
  F->>EA: Authentification Entra
  EA-->>F: x-ms-client-principal (claims groups)
  alt Groupe du share ∉ groupes utilisateur
    F-->>U: 403 Access to this share is denied.
  else Autorisé
    F->>F: Génère SAS lecture seule, 5 min, inline
    alt Fichier Office (.docx/.xlsx/.pptx…)
      F-->>U: 302 → view.officeapps.live.com?src=SAS
      U->>O: Ouvre le viewer
      O->>S: Lit le fichier via SAS
    else PDF / image / texte
      F-->>U: 302 → URL SAS
      U->>S: Le navigateur affiche le fichier
    end
  end

6. Les étapes IA, dans l'ordre

  1. Embedding des chunks (indexation) — text-embedding-3-small transforme chaque chunk de 2000 caractères en vecteur 1536 dims.
  2. Choix de l'outil — l'agent gpt-5-mini décide d'appeler knowledge_base_retrieve (obligatoire pour toute question documentaire).
  3. Planification de la recherche — la knowledge base utilise gpt-5-mini (effort low) pour reformuler / découper la question, y compris FR ↔ EN.
  4. Vectorisation de la requête — le vectorizer de l'index appelle text-embedding-3-small.
  5. Re-classement sémantique — le semantic ranker d'AI Search trie les meilleurs chunks (après filtrage par groupe).
  6. Génération de la réponse — l'agent gpt-5-mini rédige en anglais à partir des seuls passages extraits, cite les sources et ajoute les liens fichiers.

≈ 10k tokens par question → quota gpt-5-mini à 500k TPM pour éviter les 429.
